# Local Testing Environment & Dual Config Management

## Overview & Core Purpose (STYL-210)

Local development and automated tests share the **same safe default**: the local Supabase CLI stack at `http://127.0.0.1:54321`, with **mock / test-only** third-party keys.

**Live credentials are never used on a developer machine.** That includes the live Supabase project (`tkoasyjvrgaglofpzduq`), and live Mailgun, Twilio, Stripe, Vapi, Gemini, Meta, or Turnstile keys. Local experiments must not change live data or message real people.

1. **`.env.local` (Day-to-day `npm run dev`)**
   - Generated by `npm run env:local` after `npx supabase start`.
   - Points at **local** Supabase (`http://127.0.0.1:54321`), not live cloud.
   - Uses mock Mailgun / Twilio / Stripe / Vapi / Gemini keys.
   - Optional: dedicated **staging** Supabase (`styleflo-staging`, see `docs/staging.md`) — never live. Reset with `npm run db:reset` (refuses the live project ref).

2. **`.env.test` (Playwright / `test:server` / Husky)**
   - Also generated by `npm run env:local` (same local keys; app URL on port 3001).
   - Used by `npm run test:e2e`, `npm run test:server`, and pre-push hooks.
   - Outbound mail is trapped in local Inbucket (`http://127.0.0.1:54324`).

> [!CAUTION]
> NEVER paste live cloud credentials into `.env.local` or `.env.test`. Doing so can mutate production data and send real emails/SMS. If you need shared cloud data, use a dedicated staging project — not live.

See `.env.example` for the full list of variable **names** (no values). Names marked **[TEST KEYS ONLY]** must stay as mocks or vendor test keys on a developer machine.

## Environment File Breakdown

| Configuration Variable | Local / test (required default) | Forbidden on a dev machine |
| :--- | :--- | :--- |
| `NEXT_PUBLIC_SUPABASE_URL` | `http://127.0.0.1:54321` (or staging) | Live project `tkoasyjvrgaglofpzduq` |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Local Supabase CLI anon key | Live anon key |
| `SUPABASE_SERVICE_ROLE_KEY` | Local Supabase CLI service role key | Live service role key |
| `MAILGUN_API_KEY` | `mock_mailgun_api_key_for_local_testing` | Real Mailgun API key |
| `STRIPE_SECRET_KEY` | `sk_test_…` / mock | Live `sk_live_…` |
| `TWILIO_*` / `VAPI_*` / `GEMINI_API_KEY` | Mocks / vendor test keys | Live production keys |
| `NEXT_PUBLIC_APP_URL` | `http://localhost:3000` (dev) / `:3001` (tests) | — |

## Runbook: Local development (safe default)

```bash
npx supabase start          # local API on 127.0.0.1:54321
npm run env:local           # writes .env.local and .env.test from supabase status
npm run dev                 # refuses to start if pointed at the live project
```

`npm run dev` calls `scripts/dev.mjs`, which regenerates env from local Supabase when `.env.local` is missing or still points at the live project.

At process start, `src/instrumentation.ts` logs a clear warning if `NEXT_PUBLIC_SUPABASE_URL` is the live project and the effective app env is not production. Production Cloud Run (`NODE_ENV=production`, `APP_ENV` unset) does **not** emit that warning.

### Step 1: Start Local Supabase DB
```bash
npx supabase start
npm run env:local
```
Verify services:
```bash
npx supabase status
```

### Step 2: Run Automated Playwright Tests
```bash
npm run test:e2e
```
Or interactive UI mode:
```bash
npm run test:e2e:ui
```

### Step 3: Local Mail Inspection
```
http://127.0.0.1:54324
```
All transactional emails from local/test runs appear in Inbucket.

## Safeguards & Troubleshooting

- **If tests report `AuthApiError: Invalid login credentials`**:
  Do **NOT** copy live credentials into `.env.test`. Ensure local Supabase is running (`npx supabase start`) and seeded (`npx supabase db reset`), then `npm run env:local`.
- **If `npm run dev` refuses to start**:
  `.env.local` still names the live project. Run `npm run env:local` (or switch to a staging URL).
- **If tests fail due to port conflicts**:
  Stop orphaned Next.js processes on ports 3000/3001.
